# 依詞語表推導單字頻次（實驗 B6）

> 結論先講：**三種變體全數使結果變差，預設維持 `off`**（產物與未導入此功能前逐位元組相同）。
> 實作保留於建置器內，以便日後以不同的訊號來源重做此實驗。

## 1. 動機

`char-kanji-core.txt` 的「頻次」欄是封頂於 7,700 的類排名值（p90 為 3,832、p50 為 0），並非語料計數。
因此在建置後的辭典中，每個讀音最常用的單字分數幾乎都擠在 −5.0 至 −5.3 之間（例：在 −5.009、再 −5.012），
同音單字之間的勝負只差千分之幾。實驗構想：以詞語表（`phrases-*.txt`）中帶有真實語料規模的計數，
為每個（字, 讀音）推導出一個頻次，用來拉開單字之間的差距。

## 2. 推導方式

對指定字形（簡體或繁體）的每個詞語條目，逐位置將該詞的頻次加到 `derived[(字_i, 讀音_i)]`，最後再加上
該字在 `char-kanji-core.txt` 中自身的頻次一次。

- 納入的詞語表：`phrases-moe-*`、`phrases-tabe-*`、`phrases-vchewing-*`。
- **排除** `phrases-custom-*`（含原神等電玩專用表），以免特定作品的專有名詞扭曲單字頻次。
- 同一（詞, 讀音）若同時出現在多張表，只計一次，取其最大頻次（避免重複計數）。
- 字數與讀音數不符的條目略過。

只調整 `.kanji` 類別中「原始頻次 ≥ 0」且「詞語推導頻次 > 0」的單字；假名（−1／−2）、注音符號、CNS、
GBEX、misc 及所有詞語皆不變動。

### Norm 的處理

推導頻次**不計入** `norm`，`norm` 與原本完全相同，因此所有詞語的分數保持不變，影響範圍只限於單字。
為了不讓單字整體與詞語整體之間的機率質量失衡，`replace` 與 `blend` 會先把推導頻次乘以縮放係數
`k = Σ原始頻次 ÷ Σ推導頻次`（只在受調整的字之間計算；繁體約為 0.011），使受調整單字的總質量維持不變。
未經縮放時，「是」的頻次會從 7,138 變成約 420 萬，單字分數整體上移約 2.8，必然造成過度斷詞。

## 3. 變體與切換方式

以環境變數 `VC_CHARFREQ_MODE` 切換（預設 `off`）：

| 模式 | 公式 |
|---|---|
| `off` | 不調整（預設）。 |
| `replace` | `count' = k · derived` |
| `blend` | `count' = original^(1−λ) · (k · derived)^λ`；λ 由 `VC_CHARFREQ_LAMBDA` 指定（預設 0.5）。原始頻次為 0 者不調整。 |
| `shift` | 保留原始頻次，於最終分數加上 `γ · (log10(1 + derived) − M)`；`M` 為受調整且原始頻次 > 0 之單字的 `log10(1 + derived)` 中位數（繁體約 3.84）；γ 由 `VC_CHARFREQ_GAMMA` 指定（預設 0.5）。 |

```sh
VC_CHARFREQ_MODE=blend VC_CHARFREQ_LAMBDA=0.5 swift run -c release VCDataBuilder vanguardTextMap
```

注意：`VanguardTextMapPlugin` 以明確指定的環境變數執行建置器，不會繼承 shell 的環境變數。
因此在 vChewing-macOS 透過 plugin 建置時，只有原始碼中的 `CharFrequencyMode.defaultMode` 會生效。

## 5. 失敗原因

「字在詞語中出現的次數」與「字單獨成詞的次數」是兩回事，而後者才是單字 unigram 該反映的量：

- 虛詞與常用單音詞很少出現在收錄的詞語中，推導頻次偏低而被壓下去：
  吧→罷（罷工、罷免）、又→右（右邊、左右）、跟→根、嗎→嘛／媽、裡→理、帶→代、就→究、往→網、忘→望。
- 構詞力強的字被抬高：作（工作、作品）壓過做與坐；市（臺北市等地名）幾乎追平是；
  shift 模式更把「件」「見」帶向「見識」等錯誤組合。
- shift 以全體中位數置中，常用字普遍獲得 +0.9～+1.5 的加分，兩個常用單字相加便能勝過正常的雙字詞，
  造成明顯的過度斷詞（種子集總分段數 362→405）。

## 6. 日後方向

詞語表無法提供「單獨成詞」的頻次。若要重做此實驗，需要的是斷詞後語料中單字詞的實際計數
（例如以現有辭典對大型語料做最大機率斷詞後，統計落為單字詞的次數），而非詞內出現次數。
屆時可直接沿用 `CharFrequencyDeriver` 的套用流程（縮放、norm 不變、`scoreBias`），只替換訊號來源。
